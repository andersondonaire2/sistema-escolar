DS QUEST MASTER
Sprint 08 - Indicadores, Acessos Recentes e Alertas de Segurança

CONTEXTO

A Missão 007 passou a registrar logins e alterações importantes no sistema.
Agora a direção precisa transformar o histórico em informação rápida para agir:

- Quantos eventos ocorreram por operação?
- Quantos logins foram recusados nas últimas 24 horas?
- Qual foi o último acesso de cada usuário?
- Existe uma sequência anormal de tentativas recusadas?

Nesta sprint, o Squad atuará como equipe de Observabilidade e Confiabilidade.

MISSÃO

Criar um painel administrativo de segurança usando os dados da auditoria.
O sistema deverá:

- exibir o total de eventos por operação;
- contar logins recusados nas últimas 24 horas;
- listar o último acesso de cada usuário;
- alertar quando o mesmo usuário tiver várias tentativas recusadas em uma janela curta;
- permitir atualização dos indicadores sem recarregar a página inteira;
- manter todos os dados visíveis somente para o perfil admin.

RESPONSABILIDADES DO SQUAD

DESENVOLVEDOR FRONT-END

Criar a tela "Painel de Segurança" dentro da área administrativa, contendo:

- cartões objetivos para os indicadores principais;
- tabela de último acesso por usuário;
- lista de alertas de tentativas recusadas;
- filtro de período;
- botão de atualizar os dados;
- estados claros para carregamento, erro e ausência de eventos.

DESENVOLVEDOR BACK-END

Criar endpoints separados para os indicadores, por exemplo:

GET /auditoria/indicadores
GET /auditoria/ultimos-acessos
GET /auditoria/alertas

As rotas devem:

- exigir token válido;
- permitir acesso somente ao perfil admin;
- reutilizar a tabela de auditoria;
- aceitar início e fim quando o indicador permitir período;
- retornar dados agregados, sem senha, token ou detalhes sensíveis.

DESENVOLVEDOR BANCO DE DADOS

Avaliar índices e consultas da auditoria para os novos agrupamentos.
Se necessário, criar índices compostos para data, operação e usuário.
Não duplicar eventos em tabelas de resumo sem uma justificativa de desempenho.

QA

Criar checklist e testes automatizados para:

- admin consultar os indicadores;
- professor receber 403;
- usuário sem token receber 401;
- totais por operação serem coerentes com os eventos criados;
- filtro de período excluir eventos fora da janela;
- último acesso considerar o evento mais recente de cada usuário;
- alerta aparecer após o limite definido de tentativas recusadas;
- resposta não conter senha, token ou hash de senha.

SCRUM MASTER

- definir o limite de tentativas que gera alerta;
- registrar a janela de tempo escolhida;
- preparar uma demonstração com login recusado, indicador atualizado e alerta;
- registrar riscos de volume e desempenho no CONTEXTO.md.

CRITÉRIOS DE VITÓRIA

- existe painel administrativo de segurança;
- os indicadores são calculados pela API;
- somente admin acessa os dados;
- o período pode ser filtrado;
- alertas de tentativas recusadas são compreensíveis;
- os testes comprovam 401, 403 e resultados agregados;
- nenhuma informação secreta aparece na API ou na tela.

BOSS CHALLENGE

Adicionar uma visão de tendência das últimas 24 horas, agrupada por hora, e
permitir exportar um relatório CSV sem incluir detalhes sensíveis.

PERGUNTAS PARA DISCUSSÃO

1. Quando um indicador deve ser calculado em tempo real e quando vale armazenar um resumo?
2. Como escolher um limite de tentativas recusadas sem gerar falsos positivos?
3. Por que o painel de segurança também precisa respeitar autorização?
4. Quais dados são suficientes para investigar um alerta sem expor segredos?
